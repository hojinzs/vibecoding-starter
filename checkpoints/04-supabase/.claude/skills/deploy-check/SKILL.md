# 배포 전 점검

점검과 보고만 해요. 문제를 발견해도 **고치기 전에 먼저 알려주고 확인을 받으세요.**

## 확인할 것

1. **빌드가 되는지**: `npm run build`를 실행해요. 실패하면 오류의 핵심 한 줄과 원인을 쉬운 말로 알려줘요.
2. **secret 열쇠가 브라우저로 나가지 않는지**
   - 코드와 `.env.example`에서 `NEXT_PUBLIC_`이 붙은 이름 중 `SECRET`, `SERVICE_ROLE`, `PASSWORD`, `PRIVATE`가 들어간 것이 있는지 찾아요.
   - `"use client"` 파일이 secret 열쇠를 쓰는 파일을 가져오고 있지 않은지 확인해요.
3. **배포 환경에 넣을 환경변수 목록**
   - `.env.example`과 코드에서 쓰는 `process.env.이름`을 모아 **이름만** 표로 보여줘요. 값은 출력하지 마세요.
   - 각 이름이 브라우저까지 나가는지(`NEXT_PUBLIC_`), 서버에만 남는지 칸을 나눠요.
4. **코드가 GitHub에 올라가 있는지**: 배포는 GitHub의 코드를 가져가요. 아직 push하지 않은 커밋이 있으면 알려줘요.
5. **파일에 저장하는 코드가 있는지**: 배포된 서버는 파일에 쓴 내용을 계속 기억하지 못해요. `fs.writeFile` 같은 저장이 있으면 배포 뒤에는 남지 않는다고 알려줘요.

마지막에 이렇게 안내해요.

- Vercel에는 **Settings → Environment Variables**에서 위 이름들을 넣어요. 값은 학습자가 직접 붙여넣어요.
- 환경변수를 바꾼 뒤에는 **Redeploy**를 해야 반영돼요.
- 배포한 뒤에는 다른 기기(휴대폰)에서 주소를 열어 확인해요.
