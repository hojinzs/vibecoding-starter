# 쉬운 말로 설명하기

**설명만 해요. 코드는 고치지 마세요.**

## 무엇을 설명할지 정하기

- 파일을 지목했다면 그 파일을 설명해요.
- "방금 바뀐 것"이라면 `git diff`(아직 add 안 한 것)와 `git diff --cached`(add한 것)를 보고 설명해요. Git 저장소가 아니면 이번 대화에서 바꾼 파일을 기준으로 해요.
- 오류 메시지라면 메시지의 핵심 한 줄을 골라 풀어요.

## 설명하는 순서

1. **누구의 일인가**: 홀 직원(화면 담당), 조리사(처리 담당), 창고지기(기록 담당) 중 누구 몫인지 먼저 말해요.
   - `"use client"`가 맨 위에 있으면 화면 쪽, 없으면 `app/` 안에서는 기본이 서버 쪽이에요.
   - `"use server"`가 있으면 화면에서 부르는 서버 쪽 처리예요.
2. **무슨 일을 하나**: 두세 문장으로. 코드 줄을 그대로 읽어주지 말고 하는 일을 말해요.
3. **화면에서는 어디에 보이나**: 학습자가 브라우저에서 확인할 수 있는 자리를 짚어요.
4. **바뀐 것이라면**: 전과 후가 어떻게 달라지는지 표로 보여줘요.

## 지킬 것

- 해요체, 짧은 문단. 낯선 용어는 처음 한 번 "쉽게 말하면 ○○예요"로 풀어요.
- 비밀 값이 들어 있는 줄은 값을 가리고 "열쇠가 들어가는 자리"라고만 말해요.
- 마지막에 학습자가 스스로 확인해볼 질문 하나를 남겨요.
