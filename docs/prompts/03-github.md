# 03 · GitHub에 소스 올리기

키트의 학습자용 규칙이 들어 있다면 "지금 상태 알려줘"(`check-status`)와 "저장해줘"(`save-progress`)로 같은 흐름을 진행할 수 있어요. 아래는 강의 원문의 프롬프트예요.

## 1. 준비 상태만 물어보기

```txt
이 프로젝트는 Next.js로 만든 스터디 신청 페이지야.
GitHub에 올리기 전에 준비 상태만 점검해줘.

확인할 것:
1. 현재 프로젝트의 실제 경로와 Git 저장소 루트
   - study-signup이 아니라 상위 폴더 전체가 저장소인지도 확인해
2. Git과 GitHub CLI(gh)의 설치 여부와 버전
3. Git 커밋에 쓸 이름·이메일 설정 여부
4. GitHub CLI의 로그인된 계정과 현재 활성 계정
5. 현재 브랜치, 기존 커밋 유무, 변경된 파일
   - 이미 add한 변경과 아직 추적하지 않는 파일도 구분해
6. 기존 remote의 연결 대상
7. .gitignore 규칙
8. node_modules, .next, .env 관련 파일이 제외되는지
   - 이미 Git이 추적 중인지도 확인해
9. 소스·설정·예시 파일에 비밀정보가 들어간 흔적이 있는지

초보자가 이해할 수 있게
'확인 항목 / 현재 상태 / 다음에 할 일' 표로 정리해줘.
확인하지 못한 항목은 이유를 알려줘.

비밀번호·토큰·키의 실제 값은 출력하지 마.
발견하면 파일 경로와 정보 종류만 알려줘.
연결 주소에도 인증 정보가 있으면 가려줘.

아직 설치, 로그인, 파일 수정, git init,
add, commit, push, 저장소 생성은 하지 마.
```

## 2. 올릴 파일 정리하기

```txt
점검 결과를 바탕으로 GitHub에 올릴 파일을 정리해줘.

1. 기존 .gitignore 규칙은 유지하면서 필요한 규칙만 보완해
   - node_modules/, .next/, 실제 .env 설정 파일, 임시 파일 제외
   - .env.example은 허용하되 실제 비밀값이 없는지 확인
   - 다른 규칙 때문에 .env.example이 계속 제외되는지도 확인
2. 제외 대상이 이미 추적되거나 커밋된 적이 있으면
   임의로 처리하지 말고 파일 경로와 영향을 알려줘
3. README.md가 없으면 만들고, 있으면 기존 설명을 보존하면서
   이번 프로젝트에 맞지 않는 기본 안내만 필요한 만큼 고쳐줘
   - 스터디 신청 페이지라는 설명
   - 실제 package.json과 잠금 파일에 맞는 로컬 실행 방법
   - 현재 신청 정보는 브라우저 안에서만 유지되고
     새로고침하면 사라진다는 안내
4. 소스 코드와 기능은 바꾸지 마

완료 후 다음을 보여줘.
- 수정한 파일과 이유
- 올릴 파일 목록과 제외할 파일 목록
- 남아 있는 문제와 직접 확인할 항목

비밀값은 출력하지 마.
아직 add, commit, push, 저장소 생성은 하지 마.
```

## 3. 내 컴퓨터에 기록 남기기

```txt
올릴 파일 목록을 확인했어.
현재 프로젝트의 변경을 Git에 기록해줘.

1. 프로젝트 루트가 study-signup인지 다시 확인해
   상위 폴더 전체가 저장소라면 멈추고 알려줘
2. Git 저장소가 아니면 이 프로젝트 루트에서
   main을 기본 브랜치로 새 저장소를 만들어
3. 기존 저장소라면 커밋과 브랜치를 유지해
   현재 브랜치가 main이 아니면 처리 방법을 먼저 제안하고 기다려
4. 이미 add된 변경이 있으면 이번 작업 범위인지 확인해
   관계없는 변경이 섞여 있으면 멈추고 알려줘
5. 확인한 파일만 추가하고 git diff --cached로
   이번 커밋에 실제 들어갈 변경을 검토해
6. 비밀정보나 제외 대상이 없다면
   "feat: 스터디 신청 페이지 화면 완성"으로 커밋해
7. 커밋할 새 변경이 없다면 빈 커밋을 만들지 말고
   기존 최신 커밋을 사용한다고 알려줘

이름·이메일이 없거나 처리되지 않은 문제가 있으면 멈춰.
기존 Git 기록, remote, 다른 사람의 변경은 지우거나 바꾸지 마.
제외된 파일을 강제로 추가하지 마.

완료 후 커밋의 짧은 식별값·설명과 남은 변경을 알려줘.
아직 GitHub 저장소 생성이나 push는 하지 마.
```

## 4. 비공개 저장소에 올리기

```txt
study-signup의 확인된 커밋을 GitHub에 올리고 싶어.

진행 전에 아래 계획을 보여주고 내 확인을 기다려.
- 현재 활성 GitHub 계정
- 저장소 소유자와 이름: 해당 개인 계정 / study-signup
- 저장소 설명: Next.js로 만든 스터디 신청 페이지
- 공개 범위: private
- 보낼 브랜치: main
- 보낼 커밋의 식별값과 설명
- 포함할 파일과 제외할 파일 요약
- 기존 remote와 같은 이름의 GitHub 저장소 유무

내가 확인하면 계획대로 진행해.
1. 현재 로컬 저장소를 사용해 비공개 GitHub 저장소를 만들어
2. remote 이름은 origin으로 연결해
3. 확인된 main 브랜치를 push해
4. 저장소 URL과 실제 공개 범위를 확인해
5. 로컬 최신 커밋과 GitHub main의 커밋이 같은지 비교해
6. 남은 변경과 연결 상태를 쉬운 말로 알려줘

규칙:
- 기존 remote나 같은 이름의 저장소가 있으면
  덮어쓰거나 다른 저장소를 만들지 말고 재사용 방법을 먼저 제안해
- public으로 만들거나 조직 소유 저장소를 임의로 만들지 마
- force push, 기록 삭제, 제외 파일 강제 추가는 하지 마
- 오류가 나면 어디까지 완료됐는지와 원인을 먼저 알려줘
- 인증 정보나 비밀값은 출력하지 마
```

설치·로그인, 커밋 작성자 설정, 문제 해결 프롬프트는 원문 4·10장에 있어요.
