## 1. 첫 배포 (직접 클릭해요)

계약서에 서명하는 일이라 에이전트에게 맡기지 않아요.

1. vercel.com에 GitHub 계정으로 로그인해요
2. **Add New → Project**를 눌러요
3. `study-signup` 저장소를 찾아 **Import**를 눌러요
4. 프레임워크가 Next.js로 자동 인식돼요. 빌드 설정은 손대지 않아요
5. Environment Variables는 비워두고 **Deploy**를 눌러요

배포 전에 점검하고 싶다면 에이전트에게 "배포해도 돼?"라고 물어보세요(`deploy-check`).

## 2. git push로 다시 배포하기

```txt
study-signup의 신청 페이지 제목 문구만 살짝 고쳐줘.
어떤 문구로 바꿀지 먼저 보여주고 기다려줘.

내가 확인했다고 답하면
그 파일만 커밋하고 main에 push해줘.

- 다른 파일은 건드리지 마
- 커밋 메시지는 "docs: 신청 페이지 제목 문구 수정"으로 해줘
```

push한 뒤 Vercel의 **Deployments** 탭에서 새 배포가 저절로 시작되는지 확인해요.

## 3. 프리뷰 배포 (실수해도 되는 자리)

```txt
study-signup에서 새 브랜치를 하나 만들어서
신청 폼 아래에 안내 문구를 한 줄 추가해줘.

1. 브랜치 이름은 try-notice로 만들어
2. 안내 문구만 추가하고 다른 기능은 건드리지 마
3. 커밋하고 그 브랜치를 push해
4. main 브랜치에는 아무것도 올리지 마

작업 전에 바꿀 파일을 먼저 알려주고 기다려줘.
```

> 체크포인트 `03-vercel`은 main 기준이라 `try-notice` 변경은 들어 있지 않아요.
